Многопоточность

---
Процесс - экземпляр запущенной программы
У него свое адресное изолированное от других место в памяти, дескрипторы файлов, сетевое окружение

Поток - это "легкий" процесс внутри процесса
Все потоки разделяют память (кучу, статические переменные), доступ к обьектам
Имееют свой собственный стек вызовов и счетчик команд

Потоки нужны:
- Эффектичнвость - создание потока дешевле создания процесса
- Параллельное выполнение - использовать многоядерные процессоры
- Асинхронность - не блокировать основной поток

Создание потока в Java:
1) Интерфейс Runnable
Лучший способ (если логика 4+ строки)
2) Лямбда-выражение
Современный, лаконичный (если логика 4- строки)
    - t.run(); - НЕ создаёт новый поток, выполняется в текущем потоке (main)
    - t.start(); - ТОЛЬКО так создаётся новый поток (run в новом потоке(обьекте класса потока))
3) Наследоваться от Thread
Самыый простой, но не рекомендуемый способ из-за одиночного наследовния

Поля внутри класса потоков private из-за инкапсуляции

6 состояний потока:
1) NEW - создан, но start() не вызван
2) RUNNABLE - выполняется или готов к выполнению
3) BLOCKED - поток ждет освобождение монитора, как монитор освобожден - захват монитора и -> RUNNABLE
4) WAITING - поток ждет уведомления без тайматуа (wait(), join()), приходит notify()\notifyAll() -> RUNNABLE
5) TIMED_WAITING - поток ждет с тамайтом (sleep(ms), wait(ms), join(ms)), проходит таймаут\приходить уведомление -> RUNNABLE
6) TERMINATED - выполнен\упал с исключением

Методы работы с потоками Thread:
- Thread.sleep(ms) - приостанавливает поток на указанное время милисекунд (может выбросить InterruptedException)
- Thread.join() - останавливает текущий поток, до тех пор пока поток у которого вызван .join() не завершится

Методы работы с потоками Object !вызываются ТОЛЬКО в synchronyzed-блоке:
- wait() - поток отпускает монитор и переходит в WAITING, пока другой поток не вызовет notify()\notifyAll() на том же обьекте
- notify() - пробуждает 1 случайный поток, который ждет на этом мониторе
- notifyAll() - пробуждает все потоки
!wait() обязательно в условном цикле

Race Condition

Отличный пример - инкремент счетчика - поломка т.к. cout++ не атомарная операция    
Решение - synchronyzed (мониторы)\AthomicInteger
Можно синхронизировать:
1) Обьект
2) Метод
3) Блок this (часть метода)
Очень удобно синхронизировать через обьект передаваемый в параметры

Synchronyzed дает две гарантии:
1) Атомарность - блок выполняется как единая неделимая операция
2) Видимость - все изменения, сделанные в блоке, будут видны другим потокам
